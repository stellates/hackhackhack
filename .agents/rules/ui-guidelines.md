# UI & リズムノーツ視認性設計基準（デグレ防止ガイドライン）

本ドキュメントは、「THE HOLLYWOOD HACKER」におけるリズムノーツの視認性、画面内ガイド、およびテキスト可読性を担保し、今後の機能追加やアップデートでのデグレを防止するための絶対遵守ルールです。

---

## 1. キー・カラー完全同期原則（Color & Key Consistency）

ゲーム内で使用する4つの操作種別は、ノーツ・HUD・ガイド・モバイルボタン・説明文のすべてで同一色・同一ラベルを完全同期させること。

| 操作種別 | カラーコード | 代表色 | ノーツ表記 | HUD / ガイド表記 | アクション |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **連打ゾーン** | `#00ff88` | 🟢 ネオングリーン | `⚡ 連打 (ANY KEY) ⚡` | `ANY KEY` 連打 | 任意キー猛烈連打 |
| **SPACE** | `#ffd700` | 🟡 エレクトリックゴールド | `␣ SPACE` | `SPACE` | 単打（下段レーン） |
| **SHIFT** | `#ee77ff` / `#cc44ff` | 🟣 ネオンパープル | `⇧ SHIFT` | `SHIFT` | 単打（上段サブレーン） |
| **ENTER** | `#ff3377` / `#ff0055` | 🔴 クリムゾンレッド | `↵ ENTER` | `ENTER` | 強打（下段レーン） |

### 遵守事項
- **SPACEノーツにシアン（水色）を使用してはならない**。水色はターミナルの基本UI色であり、SPACEと混同するためゴールドで完全統一する。
- **謎の日本語設定用語（防壁突破、加速バイパス、ペイロード強打等）をノーツやHUDバッジに併記してはならない**。プレイヤーが迷うため、緑の「連打」のみを除き、キー名とピクトグラム単体とする。

---

## 2. 高速移動ノーツの文字ブレ根絶設計（ピュア・ネオンクリスタルブロック）

毎秒260〜370pxで高速スクロールするノーツに対して、以下のレンダリング・デザイン仕様を維持すること。

1. **ノーツ内のテキスト・記号の完全排除**:
   - 移動するノーツ内部に文字（`SPACE`, `ENTER` 等）や記号（`␣`, `⇧`, `↵` 等）を配置してはならない。
   - 動く文字を「読もう」とする認知負荷および文字ブレを原理的にゼロ（100%根絶）にするため、ノーツは**「文字なしのソリッドな光るネオンクリスタルブロック／帯」**として描画する。
   - プレイヤーはタイピングエリア直上の大判キーマップHUD（`KEY MAP`）と「色」（緑、黄、紫、赤）のみで1対1直感識別する。
   - 各単打ノーツの中央には垂直のホワイトコアライン（芯）を配置し、照準枠とのジャストタイミング判定を明確にする。
2. **サブピクセル補間の排除**:
   - 移動するノーツ要素に `transform: translateY(-50%)` を使用してはならない。
   - Y軸の配置はCSSの整数ピクセル `top: Xpx` で固定し、`transform` は `translate3d(Xpx, 0, 0)`（X軸のみ）で移動させる。
3. **GPUアクセラレーション**:
   - 移動するノーツ要素には `will-change: transform;` および `backface-visibility: hidden;` を必ず付与する。

## 3. 画面内常時キーマップHUDの維持

1. **単一の配置場所（上部一本化）**:
   - プレイヤーの視線が集まるタイピングエリア（ビートハイウェイ）の直上に、大判の `.terminal-key-legend-bar` を常時配置すること。
   - 画面右下など別の場所に重複した凡例を配置してはならない（画面の情報過多を防ぐ）。
2. **打鍵フィードバック連動**:
   - キー打鍵時（またはモバイルボタン押下時）には、該当するHUDキーが瞬時に発光（`.key-pressed`）し、プレイヤーが自分の押したキーと色の対応を体感できるようにすること。

---

## 4. 読ませるべきテキストの可読性基準

1. **CRTスキャンラインのモーダル干渉禁止**:
   - CRTスキャンラインオーバーレイ（`.crt-overlay`）はゲームプレイ中の背景・ターミナル演出用である。
   - スタートモーダル（`#start-modal`）および結果モーダル（`#result-modal`）は `z-index: 1000;` とし、走査線の黒縞が文字の上に重なって可読性を損なうことを禁止する。
2. **日本語長文におけるシステムゴシック体の適用**:
   - 装飾コードや数字には等幅フォント（`var(--font-mono)`）を残すが、ルール説明やツッコミ寸評など「読ませる日本語文章」にはモダンなシステムゴシック体（`sans-serif`）を適用し、等幅フォント特有の字間の間延びを防ぐ。
3. **フォントサイズ基準**:
   - ルール説明本文: 最小14px、コントラスト比4.5:1以上（`#e6f0fa` 等の明色）。
   - 結果画面の称号: 最小18px〜20px（太字・ハイライト色）。
   - 結果画面のAIツッコミ: 最小14px〜15px、行間1.6。

---

## 5. 結果画面・HUD予告バナーのレイアウト設計基準

1. **NEXT予告バナーの配置**:
   - 流れてくるノーツの視認性を邪魔しないよう、ビートハイウェイ（ノーツレーン）内への配置を禁止する。
   - 一段下のタイピング文字プレビューエリア（`.terminal-content`）の右上（`top: 12px; right: 14px;`）にHUDタグとして配置すること。
   - 文言には大げさな日本語設定用語（防壁突破等）を混在させず、`NEXT: [KEY] (あと X.Xs)` の形式とする。
2. **結果モーダルのアクション配置**:
   - **左上戻るボタン**: モーダル左上に `#btn-modal-back`（`← BACK`）を独立配置し、下段アクションと視覚的・機能的に分離する。
   - **下段アクションバー**: `[認定証DL] | [結果をCOPY] | [RETRY] | [POST (X)]` の4ボタンを均等・横一列に整列させる。
3. **グリフアイコン（SVG）の適用**:
   - 絵文字（📥, 📋, 🔄 など）による安っぽい印象を排除し、SVGによる精密なベクターアイコンをPrefixマークとして使用する。
   - ボタンの高さ（44px）・パディング・角丸（5px）を統一し、各機能（DL: 緑、COPY: 水色、RETRY: 金、X: 白）に応じたネオングローを与える。
4. **X (Twitter) 共有におけるWeb Intent仕様**:
   - OS共有シート等の複雑なダイアログを挟まず、クリック時に直接 **Twitter Web Intent**（`https://twitter.com/intent/tweet?text=...&url=...`）を新規ウィンドウで開く。
   - 同時に認定証画像をクリップボードに自動コピーし、画面上に「🚀 X投稿画面を開きました！（認定証画像は Ctrl+V / ⌘V で貼り付け可能）」というトースト通知を出すことで、ユーザーが投稿画面で即座に画像を添付できるようにする。
